# The review of 2026-11-16: two faults of the measure tools

Date: 2026-11-16. Base: `69e95d4`. A review of the repository found two faults that touch what a measure says.
Neither changes a bot of one kind.

## 1. One kind against itself was played two times

`tools/arena.js --a X --b X --sides both` played two orders with the same kinds and the same seed. The second
match is the first again, so each round counted two times:

```sh
node tools/arena.js --a fatal --b fatal --maps de_dust2 --rounds 3 --seeds 1,2
# before: 4 matches, 12 rounds (each seed two equal lines). After: 2 matches, 6 rounds.
```

The records before 2026-11-13 used `--sides once` for these runs and are correct. Two records used `--sides both`:
`2026-11-13-feet.md` and `2026-11-15-empty-clip.md`. Each has a correction. Their shares stay; the count of
different rounds is half, so the error is about 1.4 times larger.

## 2. Two kinds of fatalbot in one process shared the grenades of the first

`grenadesOf` and the solved throws lay on the graph of the level, which all brains of a level share (`nav.js
navOf`). The first brain that asked decided the answer for the others. In `--a fatal-nades --b fatal` the plain
bots bought grenades in the half where they asked second. The key is now the content of a brain's own lineups
(`grenades.js lineupCache`).

```sh
node tools/arena.js --a <a> --b <b> --maps de_dust2,de_inferno --rounds 4 --seeds 1,2
```

| Pairing | Before against after |
|---------|----------------------|
| `fatal` against `ref` | the same output, line for line |
| `fatal-nades` against `ref` | the same output, line for line |
| `fatal-nades` against `fatal` | different, as it must be: the plain bots buy no grenade now |

No record in this folder used a run of two kinds of fatalbot. The page and the room of csbih-player give the brain
no lineups, so they do not change.
